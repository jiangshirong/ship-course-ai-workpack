# 环境与工具

目标环境：Windows、能操作本地文件的AI Agent和Python；如果最终要求是真实DWG，再增加AutoCAD或其他已验证的DWG保存引擎。建议Python 3.11或更新版本；本次实际验证范围见版本记录.md，不代表所有版本组合均已验证。不要依赖整理者的用户名、盘符、Codex缓存或MCP路径。

公开依赖见requirements.txt，可用 `python -m pip install -r requirements.txt` 安装。openpyxl读写XLSX，ezdxf操作DXF，numpy用于计算，matplotlib用于预览，pywin32用于AutoCAD COM。

## CAD软件和MCP：分层使用

没有 AutoCAD 不会阻止主要开发。AI 可以用 `ezdxf` 生成和重新读取 DXF，用几何脚本检查闭合、坐标、间距、图层、文字、尺寸实体和构件连接，再用 LibreCAD、QCAD 或其他 DXF 查看器做人工/截图复核。这一层足够完成大多数设计迭代，适合没有 AutoCAD 的使用者。

如果最终要求必须是真实 DWG，则需要再增加一个已验证的 DWG 保存环节。优先使用 Windows AutoCAD，因为其 ActiveX/COM 文档明确提供 `Document.SaveAs`：[Autodesk ActiveX 文档](https://help.autodesk.com/cloudhelp/2020/ENU/AutoCAD-ActiveX/files/GUID-EF30D5C5-6A02-48FE-82C9-14E0EAEAFB79.htm)。也可以研究其他 DWG 引擎，但必须用本项目的样例实测保存、重新读取、文字、尺寸、图层和布局；不能把 DXF 改后缀当作真实 DWG。

CAD MCP 是 AI Agent 的可选适配器。它能减少手动操作并帮助 AI 在 AutoCAD 中保存和回读文件，但不是开发 DXF 的必要条件，也没有证据证明某一个 MCP 在所有环境中最好。当前使用的路线是 AutoCAD COM；例如 U-C4N 的公开项目同时提供 live AutoCAD COM 和 headless ezdxf 后端，但项目页面的横向评分属于作者自己的自评：[U-C4N/AutoCAD-MCP](https://github.com/U-C4N/Autocad-MCP)。不同 MCP、AutoCAD 版本和 AI 客户端应在本机单独预检，不要把某个仓库地址写死成工作包的唯一安装方式。

本包的检查分为三层：

1. **无 AutoCAD 开发层**：生成 DXF，运行几何/结构/文字/尺寸检查，并用其他 DXF 软件查看；结果可以作为工作成果和待转换中间文件。
2. **DWG 转换层**：用 AutoCAD 或其他已验证引擎保存真实 DWG，并记录转换方式。
3. **原生 DWG 验收层**：重新打开保存后的 DWG，检查字体、线型、尺寸、布局、实体位置和视觉遮挡。只有完成这一层，才能声称“真实 DWG 已验收”。

推荐预检顺序：先完成无 AutoCAD 开发层；有 AutoCAD 时手动打开一个副本 DXF 并另存 DWG；有 MCP 时再确认它能打开、保存、关闭自己创建的文档并回读结果。没有 AutoCAD 时，明确报告“DXF 已完成，原生 DWG 尚未保存/验收”。

## 辅助工具
- `python scripts/read_input.py inputs/老师参数.xlsx --name 姓名`：读取匹配行和格式，不替你判定表头或取整。
- `python scripts/restore_reference_book.py templates/T/workbook.json work/reference.xlsx`：恢复历史公式表和基础布局供AI改写；不是个人作业生成器，不计算公式。
- `python scripts/dxf_to_dwg.py work/姓名/project.dxf outputs/姓名/姓名_проект.dwg`：在本机AutoCAD可用时另存DWG，拒绝覆盖，只关闭自己打开的文档。可用--progid指定已安装的版本；没有AutoCAD时不要运行后假称完成。
- `python scripts/check_delivery.py outputs/姓名 姓名`：检查交付目录是否只含原文姓名的DWG和俄语XLSX，并拦截DXF、DWL/DWL2、中文表格和其他中间文件。

优先使用已安装Excel或LibreOffice重算并核对版式；没有时可用scripts/recalculate.py处理本包已覆盖的标量公式，详见公式引擎与验证.md。其输出是独立子集引擎的结果，不等于Excel验证。openpyxl本身不会计算公式。遇到不支持的公式必须中止或换引擎，不允许吞掉错误。

T型参数化、几何检查和16组型材枚举分别见scripts/prepare_t_model.py、check_geometry.py、select_profiles.py。最终缓存用validate_xlsx.py验收，T型实际工作簿用check_t_assignment.py检查。使用边界见T型参数化.md。运行scripts/verify_examples.py检查5组已知算例，test_workpack.py检查辅助工具回归。

DWG转换使用pywin32 dynamic dispatch连接，再以显式IDispatch访问已知属性/方法，减少返回对象类型信息错误；不依赖当前活动文档保存。真实AutoCAD SaveAs依据[Autodesk文档](https://help.autodesk.com/cloudhelp/2023/CHS/AutoCAD-ActiveX-Reference/files/GUID-ED0D0B02-25FC-4ED2-9DEE-2B0C9AA9416A.htm)。失败按AutoCAD转换排障.md处理，可人工另存并记录。转换成功仍需打开最终DWG核对。

若已有AutoCAD MCP，可按所用实现选较小的工具配置以降低上下文开销；工具数量和配置名称依版本变化。本包不要求安装某个特定MCP，也不自动修改用户的MCP配置。

历史JavaScript里的@oai/artifact-tool不是公开必需依赖，不提供内部包安装方法。它的源码仅供理解算法和表格布局。使用本包不要求Codex专有环境。
