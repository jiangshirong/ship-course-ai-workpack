# 分支与资源入口

生成任何新作业前先读[交付格式与船型制图规范](../docs/交付格式与船型制图规范.md)。它规定最终只交 DWG 与俄语 XLSX、五类基本视图、俄文姓名及 T/C 分支的图纸表达；本页只说明计算模板和历史资源。

**T型固定拓扑：** 7段平底＋2段舭弧＋9段直舷侧＋7段内舷侧；3个平台；最多14对货舱甲板纵骨、恰好2对双舷侧甲板纵骨。骨材检查包含主表12组和中纵舱壁CL-F1～4，共16组。超过该拓扑必须扩展行、公式、数量和CAD，不能截断或假装适用。

先读[字段契约](../docs/输入字段契约.md)和[模板已知问题](../docs/模板已知问题.md)：历史Балки!E22/E23共用压力；Листы仍存在旧控制点/混合包络；附加立柱不能漏检。公开历史底稿不是新船正确答案。

| 分支 | 入口 | 状态 |
|---|---|---|
| T | T/workbook.json、example_results.json | 修订油船样本，132×23.9×14.1 m；数字不是默认输入 |
| T后续修正 | T/corrected_section_workbook.json、corrected_section_results.json | 另一油船的内舷侧、中纵舱壁及几何协调修正；参数不同，不能整表覆盖 |
| C纵骨架 | C_longitudinal/model.json、workbook.json | 教师要求按 109 m 示例加强甲板、船底时使用；上甲板/船底/内底纵骨架，舷侧横骨架，下层甲板按 C 示例保留横梁并加强纵桁，双层底桁架按示例加强 |
| C横骨架 | C_transverse/model.json | 只有本次教师明确指定“全横骨架”时使用；不能与 C纵骨架 的纵骨、舱口边纵桁和选型表混用 |

workbook.json保留各sheet非空单元格、公式/文字、历史缓存、数字格式、合并区与列宽，未保留全部视觉样式。model.json中cells是C型公式，花括号用于变量引用；values和选型/几何都是旧计算值。
T型cell_mapping.json映射逻辑地址到工作簿地址；sheet_names.json仅保留表名映射。
cad_manifest.json为历史清单，不是本包本次检查结果。
T/base_geometry.dxf是T型绘图源码依赖的匿名基础几何，不是新船最终图。脚本保留部分旧实体，AI必须确认继承轮廓仍适用，不能只更新标注。

## 迁移历史源码
reference_code的文件以.txt结尾，供AI阅读，禁止原样当作通用程序运行。

| 历史依赖 | 当前处理 |
|---|---|
| integrate_23_09/mapping.json | T/cell_mapping.json |
| prepared.json中的oldName/name | T/sheet_names.json；表内容用workbook.json |
| 其他学生XLSX | 从本包公式底稿创建本次表，不能找回个人原文件 |
| klara/user_final.dxf | T/base_geometry.dxf |
| results.json、model.json | 由本次参数重新生成，模板值仅参考 |
| 原工作/输出目录及姓名 | 改为项目相对路径和当前姓名 |
| @oai/artifact-tool | 历史私有实现，迁移为公开工具或当前AI的实际表格能力 |
| 固定跨度/坐标/板宽/数量/断言/标注 | 全部审查，改为新船真实数据 |

保留算法是为了不丢计算链，不代表已证明所有公式正确。旧样本断言不是新船独立验证。

2026-09-25新增参数化工作副本入口：先读docs/T型参数化.md，用scripts/prepare_t_model.py将本次配置转换为工作草稿。历史底稿保持原样供追溯；其中固定2000 mm余量和旧HP行号不能直接作为新船设计。新草稿消除这些位置的硬编码并清除旧缓存，但不代表其余设计过程自动完成。

两条 C 分支都保留，是为了记录课堂中出现的不同明确要求。若用户同时提供旧的“全横骨架”和后来的“按 C 型示例加强甲板、船底”信息，AI 必须先按时间和教师针对本次作业的最新要求选一条，并在 `work/` 记录；不能凭船长自动切换，更不能把两个分支的图纸和计算页拼接。
